# Golang

Почему именно задачи инфраструктуры так хорошо ложатся на Go?

Потому что у инфраструктурных задач обычно есть такой профиль:

- много I/O, а не сложной бизнес-логики;
- много сети;
- много параллельности;
- важна надёжность и простота эксплуатации;
- важна читаемость кода командой;
- нужен маленький operational overhead;
- нужен удобный CLI или демон;
- не хочется тянуть тяжёлый runtime.

Go прямо оптимизирован под этот профиль.

Типичные инфраструктурные задачи:

- HTTP/gRPC-сервисы
- reverse proxy, load balancer
- сервис-дискавери
- агенты мониторинга и логирования
- CI/CD-утилиты
- DevOps/Platform CLI
- Kubernetes operators/controllers
- очереди, consumers, workers
- сетевые демоны
- инструменты для работы с файлами, конфигами, облачными API

Но Go особенно хорош там, где логика относительно прозрачная, а ценность — в надёжности сервиса, простоте эксплуатации и высокой конкурентности. Когда же доменная логика становится очень насыщенной, у Go начинают заметнее проявляться его ограничения.
