# Компоненты должны быть сцеплены по смыслу, а не по удобству

Частая ошибка: собрать в один класс всё, что “относится к пользователю”, хотя там намешаны несвязанные вещи.

## Плохо

Это не модуль, а склад.

```ruby
class UserManager
  def create_user; end
  def send_email; end
  def export_csv; end
  def calculate_discount; end
  def archive_logs; end
end
```

## Лучше

```ruby
class UserCreator; end
class UserExporter; end
class DiscountCalculator; end
class EmailNotifier; end
```

Или группировать по смысловой границе:

```ruby
module Billing
  class DiscountCalculator; end
end

module Export
  class UserCsvExporter; end
end
```

Cohesion = вещи, которые естественно меняются вместе. "Всё про User" — плохой критерий. Хороший модуль можно описать одной фразой без "и ещё ..."
