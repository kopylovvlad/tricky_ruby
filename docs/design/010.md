# Архитектура — это управление направлением зависимостей

Вопрос не в том "сколько у меня файлов", а:

- кто о ком знает?
- может ли верхний уровень существовать без нижнего?
- можно ли заменить нижний без переписывания верхнего?

Хорошее направление:

- domain ничего не знает про Rails
- use case ничего не знает про ActiveRecord
- adapter знает про domain
- entrypoint собирает всё вместе

## Мини-структура

```ruby
# domain
class Invoice
  def unpaid?
    status == :unpaid
  end
end

# use case
class SendReminder
  def initialize(invoice_repo:, notifier:)
    @invoice_repo = invoice_repo
    @notifier = notifier
  end

  def call(invoice_id)
    invoice = @invoice_repo.find(invoice_id)
    return unless invoice.unpaid?

    @notifier.deliver(invoice)
  end
end

# infra
class ActiveRecordInvoiceRepo; end
class EmailNotifier; end
```

Зависимость должна идти внутрь, к более стабильному коду. Фреймворк — деталь, а не центр мира. Слой orchestration не должен содержать доменную логику
