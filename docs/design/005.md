# Однородность парадигмы внутри модуля

Не смешивать бессистемно ООП, FP, мутацию, сервисные объекты, глобальное состояние и процедурщину в одном куске. Не потому, что "так нельзя", а потому что смесь ломает модель мышления.

## Плохо

```ruby
class PriceCalculator
  def initialize(items)
    @items = items
  end

  def call
    total = 0
    @items.map! { |i| i[:price] * i[:qty] }
    @items.each { |v| total += v }
    total
  end
end
```

## В функциональном стиле

```ruby
class PriceCalculator
  def self.call(items)
    items.sum { |item| item[:price] * item[:qty] }
  end
end
```

## В объектном стиле

```ruby
class LineItem
  def initialize(price:, qty:)
    @price = price
    @qty = qty
  end

  def total
    @price * @qty
  end
end

class Cart
  def initialize(items)
    @items = items
  end

  def total
    @items.sum(&:total)
  end
end
```

Cмешение парадигм допустимо, но должно быть осознанным. Внутри одного модуля лучше держать один стиль мышления
