# Границы ответственности важнее классов

Это одна из самых базовых вещей. Не “сколько у меня классов”, а где проходит граница между разными задачами.

Скрипт почти всегда содержит несколько слоёв:

- получение входа
- валидация
- бизнес-логика
- работа с внешним миром
- вывод результата

Плохой код смешивает это в одной функции. Хороший — разводит.

## Пример плохого скрипта

Тут всё смешано: CLI, чтение файла, парсинг, фильтрация, HTTP, логирование

```ruby
require "json"
require "net/http"

file = ARGV[0]
data = JSON.parse(File.read(file))

data["users"].each do |user|
  next unless user["active"]

  uri = URI("https://api.example.com/notify")
  res = Net::HTTP.post(
    uri,
    { email: user["email"], name: user["name"] }.to_json,
    "Content-Type" => "application/json"
  )

  puts "#{user["email"]}: #{res.code}"
end
```

## Лучше

```ruby
class UserFile
  def self.load(path)
    JSON.parse(File.read(path)).fetch("users")
  end
end

class ActiveUsers
  def self.call(users)
    users.select { |u| u["active"] }
  end
end

class Notifier
  def initialize(http_client)
    @http_client = http_client
  end

  def notify(user)
    @http_client.post("/notify", email: user["email"], name: user["name"])
  end
end

class CLI
  def initialize(loader:, selector:, notifier:)
    @loader = loader
    @selector = selector
    @notifier = notifier
  end

  def call(path)
    users = @loader.load(path)
    @selector.call(users).each do |user|
      result = @notifier.notify(user)
      puts "#{user["email"]}: #{result}"
    end
  end
end
```
