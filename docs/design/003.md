# Зависеть от абстракции, а не от конкретного механизма

Код верхнего уровня не должен быть женат на конкретной реализации

## Плохо

```ruby
class ReportSender
  def call(report)
    Slack::Notifier.new(ENV["SLACK_WEBHOOK"]).ping(report)
  end
end
```

## Лучше

Теперь ReportSender не знает, Slack это, email или stdout.

```ruby
class ReportSender
  def initialize(messenger:)
    @messenger = messenger
  end

  def call(report)
    @messenger.deliver(report)
  end
end

class SlackMessenger
  def deliver(message)
    Slack::Notifier.new(ENV["SLACK_WEBHOOK"]).ping(message)
  end
end
```

Зависимость — это архитектурный выбор. Чем ниже слой, тем больше конкретики. Чем выше слой, тем больше абстракции. Хороший код умеет пережить замену механизма доставки
