# Ошибки — часть архитектуры, а не хвост

Большинство пишет про happy path, но архитектурный код хорошо знает:

- какие ошибки возможны
- где их ловить
- где переводить в бизнес-смысл
- где ретраить, а где падать

Особенно остро эту парадигму показывает golang

## Плохо

Проглотили всё

```ruby
def call
  api.fetch_data
rescue StandardError
  nil
end
```

## Лучше

```ruby
class FetchUser
  def initialize(api:)
    @api = api
  end

  def call(id)
    @api.fetch_user(id)
  rescue Timeout::Error => e
    raise ExternalServiceTimeout, e.message
  rescue Api::NotFound
    nil
  end
end
```

Low-level exceptions не должны течь бесконтрольно наверх. Ошибки надо нормализовать. Retry — архитектурное решение, не просто rescue. Fail-fast лучше, чем silent corruption
